# 硬件与联调

目标为 ESP32-S3，DS18B20 使用外部供电模式。2026-11-23 已通过 COM3 的 FTDI USB-UART 识别到 ESP32-S3 revision v0.2 并成功烧录，实时读到 22.25–22.31 °C；此读数未用参考温度计校准。

| DS18B20 | ESP32-S3 |
| --- | --- |
| VDD | 3.3V |
| GND | GND |
| DQ / DATA | GPIO16（本次接线） |
| 上拉电阻 | DQ 与 3.3V 之间 4.7kΩ |

三针模块可能自带上拉，先核对板上电阻和引脚丝印；防水探头不能仅凭线色判断接线。禁止把 DQ 上拉到 5V。确认 GPIO16 未与具体开发板其他外设冲突。本版不使用寄生供电，也不驱动实体显示屏。

每两秒发起一次 12-bit 转换，等待至少 800ms 后读取。使用 DallasTemperature 的 CRC 检查；-127°C 表示断线；单次 85°C 先视为上电疑值，必须下一次完整转换仍为 85°C 才接受。自动重连 Wi-Fi，每个采样周期重新发现探头。

本次联动使用 USB 串口 COM3、115200 baud 读取 JSON 测温帧，不需要先配置 Wi-Fi。主机侧串口桥把合法测温帧提交至本机温度服务。打开串口会使多数 ESP32-S3 USB-UART 板复位，随后重新采温。可选 HTTP 传输仍需配置 Wi-Fi、局域网地址与设备 Token；DeepSeek API Key 始终留在电脑。

建议联调步骤：编译 → 人工检查接线与供电 → 确认串口后上传 → 串口见采样帧 → 面板见真实温度 → dsh 查询工具 → 普通聊天的实时上下文 → 拔掉探头 → 恢复 → 关闭 ESP32 等待 10 秒确认过期 → 重启电脑服务验证恢复。

温度准确度需用独立温度计做多点对比；探头位置、封装、线长和热平衡时间都影响读数。软件通过不代表实物或标定验收通过。

## v0.4.0 公开固件与浏览器刷写

公开映像面向 ESP32-S3 DevKitC-1-N8（8MB Flash、无 PSRAM）或布局相同的兼容板，DQ 固定默认 GPIO16。构建使用 `TEMPERATURE_PUBLIC_BUILD`，忽略本地 secrets.h，未配置 Wi-Fi 或设备 Token；USB 测温无需网络凭证。

公开固件同时向 UART0（TX43/RX44，开发板 USB-UART 口）和原生 USB CDC 输出测温帧；使用哪一个口取决于开发板接线。两个接口均出现时在面板选择其中一个。新双通道版本已编译，尚未在实板上分别刷写验证；历史 COM3 实测属于旧 UART0 固件。

新手可在静态宣传页或本机面板打开刷写页，用 Edge/Chrome 手动选择设备。若本机采集正在运行，先点“暂停采集”；页面检查 ESP32-S3 芯片及至少 8MB Flash，但不能自动确认整个板型布局。使用者核对板型并勾选覆盖确认后，才允许写入。SHA-256 验证配套下载，刷写过程由 esptool 校验 MD5。刷写完成后点击“断开并恢复采集”，等待面板有效读数。

维护者在已准备 PlatformIO 的 Windows 环境中执行 `npm run firmware:public`，再执行 `npm run flasher:build`。构建脚本通过临时 ASCII 盘符解决中文路径问题，公开合并镜像位于 `.local/public-firmware/firmware.bin`。浏览器刷写会覆盖配套分区内旧程序，只应在专用、兼容开发板上操作。
