# 大语言模型（LLM）简介

> 面向普通读者的入门介绍：它是什么、怎么工作、能做什么、不能做什么，以及日常使用时的注意事项。

---

## 一、一句话定义

大语言模型（Large Language Model，LLM）是一种经过海量文本训练、能够理解并生成自然语言的神经网络程序。你给它一段文字（提示词），它预测接下来最可能出现的文字，并一个字一个字地输出下去。

ChatGPT、Claude、DeepSeek、Gemini 等聊天助手，背后都是这类模型。

---

## 二、它是怎么工作的

### 1. 核心任务：预测下一个词

LLM 的基本训练目标是"给定前文，预测下一个 token"。token 是文本被切分后的最小单位，可能是一个字、一个词或词的一部分。模型把一段话切成 token 序列，逐位预测下一个 token 的概率分布，再按某种采样策略选出一个，接到末尾，循环往复。

看似简单，但"预测下一个词"要做到准确，模型必须隐式学会语法、事实、逻辑、文风，甚至一定的推理能力。

### 2. 三个训练阶段

| 阶段 | 做什么 | 得到什么 |
| --- | --- | --- |
| 预训练 | 在海量文本上做下一个词预测 | 基础模型：懂语言、有知识，但不会"对话" |
| 监督微调（SFT） | 用人工编写的高质量问答对训练 | 会按指令回答 |
| 对齐（RLHF / DPO 等） | 用人类偏好反馈调整 | 更有用、更安全、更符合人类习惯 |

### 3. 参数与规模

模型内部有大量可调参数（常见量级从几亿到上千亿）。参数越多，通常能力越强，但训练和运行成本也越高。近年来除"堆参数"外，还有两条重要路线：

- **数据质量**：更好的数据比更多数据更有效。
- **推理时计算**：让模型在回答前"多想一会儿"（如思维链、推理模型），用更多计算换更高质量。

### 4. 生成时的两个关键旋钮

- **温度（temperature）**：控制随机性。低温度更确定、更保守；高温度更发散、更有创意。
- **上下文窗口（context window）**：模型一次能"看到"的 token 数量上限。超出部分会被截断，所以长文档需要分段处理。

## 三、能力与边界

### 擅长

- 写作、改写、翻译、摘要
- 代码生成与解释
- 信息检索后的归纳整合（配合检索）
- 按格式输出结构化内容（JSON、表格、清单）
- 头脑风暴、方案草拟

### 不擅长 / 需要注意

| 问题 | 说明 |
| --- | --- |
| **幻觉** | 会一本正经地编造事实、引用、数据。越冷门、越具体的问题越容易编。 |
| **知识截止** | 训练数据有时间上限，之后的事它不知道，除非联网检索或你提供。 |
| **上下文限制** | 一次能读的量有限；超长对话会"遗忘"前面内容。 |
| **推理不稳定** | 多步计算、严格逻辑容易出错，且同样的题换种问法可能答案不同。 |
| **算数与精确性** | 大数运算、日期推算、精确计数不可靠。 |
| **没有真正的"理解"** | 它基于统计模式，而非人类式的因果理解与真实世界经验。 |
| **隐私** | 输入内容可能被用于训练或存储，敏感信息要谨慎。 |

## 四、常见的使用方式

### 1. 提示词工程（Prompting）

- **系统提示（system prompt）**：设定角色、规则、输出格式。
- **少样本示例（few-shot）**：给几个"输入→输出"样例，让模型照葫芦画瓢。
- **分步思考（chain-of-thought）**：让它先列步骤再给结论，复杂题更稳。
- **明确输出格式**：要求"只输出 JSON""用表格""不超过 100 字"。

### 2. 检索增强生成（RAG）

先从你的资料库检索相关片段，再连同问题一起交给模型回答。好处是：知识可更新、答案可溯源、减少幻觉。适合企业知识库、文档问答。

### 3. 工具调用与 Agent

给模型配"工具"（搜索、计算器、代码执行、API），让它自己决定何时调用、如何组合，完成多步任务。Agent 就是"会规划、会调工具、会自我检查"的 LLM 应用形态。

### 4. 微调与蒸馏

- **微调（fine-tuning）**：用领域数据继续训练，让模型更贴合特定任务或风格。
- **蒸馏（distillation）**：让小模型学习大模型的输出，用更低成本获得接近的效果。
- **量化（quantization）**：压缩模型以便在本地或边缘设备运行，代价是精度略降。

## 五、术语小词典

| 术语 | 含义 |
| --- | --- |
| Token | 文本切分后的最小单位，模型按 token 计费、计数 |
| 上下文窗口 | 一次能处理的 token 上限 |
| 提示词（Prompt） | 你输入给模型的全部内容 |
| 幻觉（Hallucination） | 模型编造看似合理但不真实的内容 |
| RAG | 检索增强生成，先查资料再回答 |
| Agent | 能规划并调用工具的模型应用 |
| 参数（Parameter） | 模型内部的可学习数值 |
| 推理（Inference） | 模型生成回答的过程 |
| 知识截止 | 训练数据覆盖的最后时间点 |
| 温度（Temperature） | 生成随机性参数 |

## 六、怎么判断一个回答靠不靠谱

1. **来源可查吗**：涉及事实、数据、引用，要求它给出可验证的来源。
2. **一致吗**：换一种问法再问一次，看结论是否稳定。
3. **格式对吗**：结构化输出是否严格符合要求。
4. **有没有"太顺"**：过于流畅、细节丰富但无法核实的回答，反而要警惕。
5. **关键决策别全信**：医疗、法律、财务等高风险领域，必须人工复核。

---

## 七、使用建议

- 把它当"能力很强但会犯错的实习生"：能大幅提效，但结果要审。
- 给足背景：目标、受众、格式、约束越清楚，输出越好。
- 敏感信息脱敏：不要在提示词里放密码、密钥、个人隐私。
- 拆解复杂任务：分步提问，比一次问一大坨更可靠。
- 保留人工判断：尤其是对外发布的内容和关键决策。
